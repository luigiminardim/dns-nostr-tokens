# Discover Workflow

## Instructions

1. **Understand the Domain:** Read the local `domain-driven-design` skill (`.agents/skills/domain-driven-design/SKILL.md`) to align your thinking with the repository's bounded contexts and ubiquitous language.

2. **Explore:** Analyze the current codebase and the user's initial prompt or idea.

3. **Draft PRD:** Use the **`github/awesome-copilot@prd`** skill to generate a comprehensive Product Requirements Document (PRD). The PRD should clearly outline the problem, proposed solution, and what is explicitly out-of-scope.

4. **Halt & Review:** Present the PRD to the user for approval. Do not proceed to defining tasks until the user confirms the PRD is accurate.

5. **Next Step Recommendation:** Once the user approves the PRD, explicitly recommend that they trigger the `2-define` workflow to plan the execution.
